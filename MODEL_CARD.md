# Model card — Verita detector

> Generated by `verita report build` from `reports/metrics.json`. Do not edit by hand.

## Intended use
Ranking account-days for review by AML analysts in a **demonstration** setting. It is trained and
evaluated only on synthetic data (IBM AML HI-Small (synthetic)). It is not validated for real customers, and no
decision about a person should rest on its score alone: every alert is reviewed by an analyst,
every case file by an MLRO.

## Model
LightGBM on 44 strictly as-of features (velocity, fan-in/out,
recency, time-respecting cycles); hyper-parameters tuned with Optuna on the hpo split only
(40 trials). Decision threshold 0.6103, chosen on
hpo for F1 and then frozen.

## Data and splits
Temporal split by transaction order: train 3,047,007 rows, hpo
507,835, calib 507,834, test 1,015,669.
Test laundering rate 0.177% vs train
0.075% — a label shift the evaluation reports rather
than hides. Only 62.0% of laundering payments belong to a labelled
typology.

## Limitations
* Synthetic data; real typologies, base rates and adversaries differ.
* Unattributed laundering (no typology label) is recalled at 0.7% (0.2%–1.9%).
* Counterparty prior-alert features were dropped: without a label-delay model they leak labels.
* Scores are not probabilities; Decide calibrates them (isotonic) before any expected-value use.
